# Bill Chaser 5000 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and deploy an Australian-hosted accounts-receivable application that synchronises Xero invoices, runs reviewable or automatic reminder sequences, sends Xero email and Sinch SMS, handles replies and opt-outs, and maintains an auditable operator workflow.

**Architecture:** A pnpm workspace contains a Next.js web/API service and a Node.js worker built from one TypeScript repository. Shared packages own the pure reminder domain, PostgreSQL persistence, Xero/Sinch connectors, authentication, job contracts, and observability; the web service records intent while the worker alone performs external sends through a PostgreSQL-backed pg-boss queue.

**Tech Stack:** Node.js 24 LTS, TypeScript 6, pnpm 10, Next.js 16.3.3, React 19.2, PostgreSQL 17, Drizzle ORM 0.45.2, pg-boss 12.33.0, Zod, Luxon, Vitest 4, Testing Library, Playwright, AWS CDK v2, ECS Fargate, RDS PostgreSQL, Cognito, Secrets Manager, KMS, and CloudWatch.

**Spec:** `docs/superpowers/specs/2026-09-18-bill-chaser-5000-design.md`

## Global Constraints

- The first release serves one Xero organisation, but every organisation-owned record includes `organisation_id`.
- Production application and database resources run in AWS Sydney (`ap-southeast-2`).
- The repository produces two containers: `web` and `worker`.
- The web service never sends a reminder directly; it persists intent and enqueues a job.
- Xero scopes are exactly `accounting.invoices accounting.contacts.read accounting.settings.read`.
- Xero Custom Connection calls omit the `xero-tenant-id` header.
- Sinch uses the APAC base URI `https://au.app.api.sinch.com`, HMAC outbound authentication, delivery reports, replies, opt-outs, and RSA secure callbacks.
- Every new reminder sequence starts in `REVIEW`; only an Admin can change it to `AUTOMATIC`.
- The application revalidates payment, status, replies, disputes, pauses, and opt-outs immediately before every send.
- An outbound request with an unknown provider result is never retried automatically.
- Production sending requires global live mode, recipient eligibility under the allowlist policy, and sequence-level approval or automation.
- Accounts are invitation-only and require TOTP MFA.
- Secrets never enter browser bundles, source control, ordinary logs, or application tables.
- Use test-driven development for each task and commit after its verification commands pass.

```ts
import { z } from 'zod';

const schema = z.object({
  NODE_ENV: z.enum(['development', 'test', 'production']),
  DATABASE_URL: z.string().url(),
  AWS_REGION: z.literal('ap-southeast-2'),
  SEND_MODE: z.enum(['dry-run', 'live']).default('dry-run'),
  LIVE_SEND_ACK: z.literal('I_UNDERSTAND_CUSTOMERS_WILL_BE_CONTACTED').optional()
}).superRefine((value, ctx) => {
  if (value.SEND_MODE === 'live' && value.LIVE_SEND_ACK !== 'I_UNDERSTAND_CUSTOMERS_WILL_BE_CONTACTED') {
    ctx.addIssue({ code: 'custom', path: ['LIVE_SEND_ACK'], message: 'LIVE_SEND_ACK is required for live sending' });
  }
});

export type RuntimeEnv = z.infer<typeof schema>;
export const parseRuntimeEnv = (input: Record<string, string | undefined>): RuntimeEnv => schema.parse(input);
```

- [ ] **Step 3: Implement deterministic eligibility**

```ts
export type EligibilityReason =
  | 'NOT_ACCREC' | 'NOT_AUTHORISED' | 'NO_BALANCE' | 'CONTACT_INACTIVE'
  | 'INVOICE_PAUSED' | 'CUSTOMER_PAUSED' | 'SEQUENCE_PAUSED'
  | 'CHANNEL_UNUSABLE' | 'CHANNEL_SUPPRESSED' | 'STAGE_COMPLETED';

export interface EligibilityInput {
  type: 'ACCREC' | 'ACCPAY';
  status: 'DRAFT' | 'SUBMITTED' | 'AUTHORISED' | 'PAID' | 'VOIDED' | 'DELETED';
  amountDue: string;
  contactActive: boolean;
  invoicePaused: boolean;
  customerPaused: boolean;
  sequencePaused: boolean;
  channelUsable: boolean;
  channelSuppressed: boolean;
  stageCompleted: boolean;
}

export interface EligibilityResult {
  eligible: boolean;
  reasons: EligibilityReason[];
}

import Decimal from 'decimal.js';

export function evaluateEligibility(input: EligibilityInput): EligibilityResult {
  const reasons: EligibilityReason[] = [];
  if (input.type !== 'ACCREC') reasons.push('NOT_ACCREC');
  if (input.status !== 'AUTHORISED') reasons.push('NOT_AUTHORISED');
  if (new Decimal(input.amountDue).lte(0)) reasons.push('NO_BALANCE');
  if (!input.contactActive) reasons.push('CONTACT_INACTIVE');
  if (input.invoicePaused) reasons.push('INVOICE_PAUSED');
  if (input.customerPaused) reasons.push('CUSTOMER_PAUSED');
  if (input.sequencePaused) reasons.push('SEQUENCE_PAUSED');
  if (!input.channelUsable) reasons.push('CHANNEL_UNUSABLE');
  if (input.channelSuppressed) reasons.push('CHANNEL_SUPPRESSED');
  if (input.stageCompleted) reasons.push('STAGE_COMPLETED');
  return { eligible: reasons.length === 0, reasons };
}
```

Add `decimal.js` to `@bc5000/domain`; do not convert monetary strings through JavaScript `number`.
